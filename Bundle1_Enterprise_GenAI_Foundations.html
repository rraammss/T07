Track 1 · How an LLM Works

What happens from your prompt to the answer

Two freezes, the tokenizer and then the brain, give one model, served over plain HTTPS.
01

One genie, many doors: the model is a file

engineering problemChatGPT, Jira and Notion look like different AIs, so teams miss the same model behind every door.
architecture focusA model is a file of weights: open models you hold (Llama, Mistral, Qwen), closed models you call over an API (GPT, Claude, Gemini). 8B, 70B and 405B differ by one number.
LIVE DEMO · Call the same model from two apps, then open a model card and read what its size counts.
02

Tokenization: the first freeze

engineering problemPrompts look like text, but the model only sees numbers, and some languages pay more for the same sentence.
architecture focusRaw bytes, then the most frequent pairs merge about 100k times; the vocabulary freezes into tokenizer.json and every prompt replays the same merges.
LIVE DEMO · Tokenize the same sentence in English and Tamil and compare the token counts.
03

Pretraining: the second freeze

engineering problemPeople imagine a fact table inside the model.
architecture focusA parameter is a learned strength, not a fact: predict, compare, loss, backprop, update, over trillions of tokens. The CPU feeds, the GPU learns, and the survivors freeze into model.safetensors.
LIVE DEMO · Watch a tiny model’s loss fall step by step, then open its safetensors file.
04

Life of one request: from frame to GPU

engineering problemSDKs hide the network, the gateways and the hardware between your app and the model.
architecture focusFrame (system, history, prompt, tools) to JSON to HTTPS, through the corporate gateway and the provider edge (401, 403, 429, 413), then the tokenizer on the CPU and the GPU forward pass, one token per loop.
LIVE DEMO · Send a raw HTTP request, then trigger 401, 413 and 429 on purpose.
05

The response comes back: stream, bill, cache

engineering problemTeams do not know why output costs more, or what streaming actually changes.
architecture focusstream: true sends SSE token by token, false sends one JSON body: same model, same bill. Input is known upfront, output costs about 5x more, and a cached prefix about 10%. The output is scanned on the way back.
LIVE DEMO · Compare a streamed and a non-streamed call and read the usage block on the bill.
Track 2 · Talking to the Model

How to control what the model does

Roles, the system prompt and sampling shape one response; the transport and the hardware decide how it reaches you.
01

Same words, two roles: system vs user

engineering problemTeams think the system prompt is technically special inside the model.
architecture focusThe same text gets the same token IDs and embeddings; only the role tag differs. Authority over instructions is learned in training: more likely obeyed, never guaranteed.
LIVE DEMO · Send identical text as system and as user, then add a conflicting instruction.
02

The system prompt, line by line

engineering problemSystem prompts grow into walls of text nobody can maintain.
architecture focusRole, success criteria, output shape, tone, domain rules, decision steps and RAG context. Every line earns its place, then decide: one call or many.
HOMEWORK · Rewrite a bloated system prompt into the seven parts and compare the outputs.
03

Temperature and sampling: every token, every time

engineering problemTemperature gets treated as part of the prompt.
architecture focusIt is generation config, held aside: logits divided by T, softmax, then sample at the LM head, inside the loop for every token. top_p, max_tokens and stop shape this response, never the model.
LIVE DEMO · Run one prompt at 0.1, 1.0 and 1.2 and compare the spread of answers.
04

One model, many front doors: REST to WebRTC

engineering problemChat, voice and internal services each need a different connection to the same model.
architecture focusREST for one shot, SSE for a server stream, WebSocket for full duplex, WebRTC for lossy UDP voice, and gRPC over HTTP/2 inside the intranet.
LIVE DEMO · Inspect each protocol in DevTools and in chrome://webrtc-internals.
05

Where the model runs: one GPU to a rack

engineering problemThe model feels like a cloud endpoint, not hardware.
architecture focusOne GPU over PCIe, one node joined by NVLink (tensor parallel), many nodes over InfiniBand (pipeline parallel), then a rack. Only the HTTP or gRPC hop is a real network.
HOMEWORK · Match five models to the smallest stage they fit on.
Track 3 · Beyond Text

How models understand images and audio

Text, images and audio all become one row of vectors, and the same transformer reads them.
01

Sending an image: one row with the words

engineering problemAn image is not tokenized like text, yet the model answers questions about it.
architecture focusThe CPU resizes and normalizes; on the GPU a ViT cuts 16x16 patches into about 256 visual tokens, a projector maps them, and they sit in one row with the words.
LIVE DEMO · Send an image with a question and trace how many patches it became.
02

The label path: pool or don’t pool

engineering problemClassifying, tagging, detecting and segmenting look like four different models.
architecture focusA frozen encoder makes patch tokens. Pool them into a class head for classify and tag; keep them unpooled to detect and segment.
HOMEWORK · Turn a classifier into a multi-label tagger with sigmoid and BCE.
03

Image training: from a file to visual words

engineering problemHow does a picture become something a transformer can learn from?
architecture focusRGB to 224x224, divide by 255, cut 16x16 tiles, learned projection to 768-D, add position, run the blocks, measure the loss, correct, and finally freeze.
LIVE DEMO · Step a tiny ViT through one training batch.
04

Self-supervised: the data is its own answer key

engineering problemNobody can write labels for billions of images.
architecture focusHide a patch and ask the model to predict it: the hidden part becomes the label, so unlabelled data can train the model.
LIVE DEMO · Mask patches and watch the model fill them in.
05

Audio: a sound becomes a picture

engineering problemSpeech looks nothing like text or images.
architecture focusDecode to a 16 kHz waveform, cut 25 ms frames, FFT, mel spectrogram, then patches into the same transformer (AST, Whisper).
LIVE DEMO · Turn a clip into a mel spectrogram and transcribe it.
Track 4 · The RAG Story

Giving the model your company’s knowledge

Same ticket, five retrievals: stuff it, words, meaning, relationships, and finally the graph that finds the fix and the owner.
01

Stuff it all in, then search by WORDS

engineering problemPasting a 1,000-page SOP costs 487K tokens, 31 seconds and $0.98 for every ticket.
architecture focusCut the SOP into 400 pieces and build a word index; a lookup returns 3 pieces for 8K tokens and $0.03. But when the operator uses different words, it finds nothing.
LIVE DEMO · Same ticket stuffed vs looked up, then a synonym that returns zero pieces.
02

MEANING search: found with zero shared words

engineering problemThe operator writes “containers”; the SOP says “pod”.
architecture focusAn embedding model turns each piece into a 1,536-number fingerprint, built once. The question gets one too, and cosine picks the closest 3. But the linked fix, P17, is missed.
LIVE DEMO · Find the right piece with no shared words, then spot the missing fix.
03

The vector store and index: embed once, persist

engineering problemVectors kept only in RAM vanish on restart, and you pay to embed them again.
architecture focusPersist the index next to a sidecar (text, pages, tenant, ACL). One process (FAISS, sqlite-vec) or a server (pgvector, Qdrant). Flat, IVF, PQ and HNSW trade speed against accuracy.
LIVE DEMO · Persist a FAISS index, restart, then compare Flat, IVF and HNSW.
04

RELATIONSHIPS: follow the arrow to the fix

engineering problemWords and meaning never read the pointer “see P17 for rollback”.
architecture focusStore the arrows and a phone book of names: enter by meaning, hop to the fix, hop to the owner. It works only where the author drew an arrow.
LIVE DEMO · Two hops to the fix and the owner, then a ticket with no arrow.
05

GraphRAG: drawing the arrows nobody drew

engineering problemThe fix exists, but no document links it to the symptom.
architecture focusDefine the ontology, extract arrows with exact quotes, verify every claim, store five tables, retrieve (find, land, hop, stop, rank, prove, pack), and summarize communities.
LIVE DEMO · Build the graph in GraphRAGLab and reach the fix for INC-78460.
Track 5 · SI Gateway

One controlled door for every model call

Insert the control without touching the app: perimeter decides if, the gateway decides what, observability records it all.
Designed here, implemented on cloud there: Path 1 defines the gateway and guardrail architecture; Path 3 maps it to AWS, Azure, and GCP services.
01

The map: perimeter, gateway, observability

engineering problemEvery team wires its own keys, limits and logs.
architecture focusLayer A, the perimeter, decides if traffic flows; Layer B, the gateway, decides what passes; Layer C, observability, records it all. All open source, all Docker.
LIVE DEMO · Walk the three-layer map and bring up the stack.
02

Two TLS links: the one plaintext point

engineering problemHTTPS is encrypted end to end, so where can a rule even run?
architecture focusThe gateway terminates TLS: one link from app to gateway, another from gateway to vendor. The middle is the one plaintext point. Explicit (change the URL) or transparent (proxy plus a trusted CA).
LIVE DEMO · Compare what a passive tap sees with what the gateway sees.
03

Three ways to insert control without touching the app

engineering problemApps cannot all be rewritten to add guardrails.
architecture focusB1, an explicit FastAPI gateway, changes the URL; A3, transparent mitmproxy, changes the environment; A1, a Squid allow-list, filters by destination.
LIVE DEMO · One app, three insertion points: 200, 403 and TCP_DENIED.
04

Virtual keys: identity, budget, routing

engineering problemA shared provider key cannot tell who called, or stop runaway spend.
architecture focusLiteLLM virtual keys run five checks: auth 401, model allow-list 403, budget and rate 429, then route and log. One key in, three vendor dialects out, and policy is data.
LIVE DEMO · Mint, limit and revoke a key without a restart.
05

Resilience and cost: limits, failover, cache

engineering problemA provider outage or a traffic spike takes every app down with it.
architecture focusToken-aware rate limits, vendor failover with timeouts, and a semantic cache for repeated questions.
HOMEWORK · Kill the primary vendor and watch traffic fail over.
Track 6 · Guardrails & Governance

Making it safe to ship

Decide what may go in, judge what comes out, harden the perimeter, and keep the proof.
Designed here, implemented on cloud there: Path 1 defines the gateway and guardrail architecture; Path 3 maps it to AWS, Azure, and GCP services.
01

Request rules: block before the provider is called

engineering problemForbidden content reaches the vendor before anyone checks it.
architecture focusBanned keywords return 403, oversized requests 413, and every verdict lands in trace.jsonl. The vendor is never contacted, and the app cannot tell.
LIVE DEMO · Send an allowed and a blocked prompt through the gateway.
02

Response filtering: schema and PII

engineering problemThe LLM already answered, and the answer may leak PII or break the JSON.
architecture focusA Pydantic schema check returns 422 and a Presidio PII scan returns 451: the analyzer finds, the anonymizer masks, in about 5 ms on the box.
LIVE DEMO · Catch a broken JSON reply and mask a name before it leaves.
03

Prompt injection: a poisoned document vs the gateway

engineering problemRetrieved text can carry instructions such as “ignore that rule”.
architecture focusSeparate trusted instructions from untrusted data, classify input with Llama Guard or Prompt Shields, and keep tool authority to the minimum.
LIVE DEMO · Plant an instruction inside a document and block it.
04

Perimeter hardening: DNS, WAF, mTLS

engineering problemThe gateway can still be bypassed at the network level.
architecture focusA DNS allow-list (Pi-hole), a WAF with the OWASP Core Rule Set (Coraza), and mTLS workload identity (Istio, SPIRE).
HOMEWORK · Block a non-approved domain at DNS and prove it.
05

Observability and audit: proof for the auditor

engineering problemWithout a record, nobody can prove what the system did or what it cost.
architecture focusLangfuse tracing, cost metering and Grafana or Loki alerts, then a comparison of what AWS, Azure and GCP enforce natively.
LIVE DEMO · Trace one request end to end and read its cost.
